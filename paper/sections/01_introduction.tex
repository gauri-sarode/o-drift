\section{Introduction}\label{sec:intro}

Recommender systems decide whether to deploy a policy by estimating its value from logs of
earlier policies, which off-policy evaluation (OPE) allows when the logs record
propensities~\cite{horvitz1952generalization,dudik2011doubly}. The logs span many weeks while
users change, loggers are replaced and click behaviour moves; what is needed is the value
\emph{now}, in a target period with only a small sample.

Pooling all history gives a low-variance estimate that is biased whenever the environment
has changed; using only the small target sample (the \emph{anchor}) is unbiased but noisy. Existing remedies interpolate
between the two along the time axis: sliding windows and moving averages~\cite{jagerman2019when},
exponential decay, forecasting the policy value as a time series~\cite{thomas2017predictive,chandak2020towards},
and regression-assisted estimators that reuse a model fitted on recent data~\cite{liu2023asymptotically}.
All of them assume that older data is less useful because it is older.

This assumption ignores what changed. A logged record is generated by three
mechanisms: the context distribution $P_t(x)$, the logging policy $\mu_t(a\mid x)$
and the conditional reward $q_t(x,a)=\mathbb{E}[R\mid x,a,t]$. The first two are
nuisances that standard tools already correct: importance weights handle the logger~\cite{agarwal2017effective},
and density-ratio transport handles the contexts~\cite{uehara2020offpolicy}.
Only a change in $q_t$ biases a correctly reweighted estimate. An old period whose users
looked different but clicked in the same way is as informative as yesterday; a recent
period after a change in click behaviour is not. Recency is a proxy for the mechanism
that matters, and a poor one when contexts or loggers drift more often than rewards.

We turn this observation into an estimator, \odrift{} (off-policy evaluation under drift). It tests for drift in the
conditional reward directly, with a per-action residual statistic computed from one
pooled reward model, and segments the history by binary segmentation. Under correct
specification the test keeps its nominal level under any context or logger drift
(Proposition~\ref{prop:invariance}), whereas statistics built from raw rewards, such
as the mean-reward similarity used by the cross-domain estimator COPE~\cite{natsubori2025cross},
do not. Within each segment \odrift{} pools windows with balanced multiple-logger weights;
across segments it fits joint reward models with a shared base and per-segment offsets,
reuses older segments after correcting their reward offset, and combines the segment
estimates with the anchor at minimum variance.

A second question is what can be seen at all. Drift \emph{between} historical windows is
observed through tens of thousands of records, so even small changes in $q_t$ are detectable;
drift between the history and the target period is observed only through the anchor, so only
large changes are. \odrift{} is \emph{observability-aware} in this sense: it segments the
history where reward drift is observable, uses the anchor only for the coarse decision of which
segment is closest to the target, and declines to certify an estimate when no anchor is available.
The same view explains its main failure: the bias of drift-corrected reuse is too small for
the anchor to observe and too large to ignore.

Our contributions are:
\begin{itemize}
\item a mechanism decomposition of drift for OPE, an observability analysis of which reward
  drift the data can reveal, and a reward-drift monitor whose size does not depend on context
  or logger drift (\cref{sec:setting,sec:method});
\item the \odrift{} estimator, with segment-wise joint reward models, drift-corrected
  reuse, minimum-variance pooling and a random-effects interval (\cref{sec:method});
\item a pre-registered evaluation on simulated regimes, semi-synthetic Open Bandit
  data~\cite{saito2021open} and Open Bandit with real clicks and natural drift, each test split
  run once, against 19 baselines including faithful implementations of COPE and
  OPFV~\cite{shimizu2025offpolicy}, with a grouping ablation that isolates the monitor
  (\cref{sec:setup,sec:results}).
\end{itemize}
We also report a negative result in full: with a misspecified reward model and large drift,
drift-corrected reuse is heavily biased, and validating reuse on the anchor or a held-out window
cannot detect that bias (\cref{sec:results}).
